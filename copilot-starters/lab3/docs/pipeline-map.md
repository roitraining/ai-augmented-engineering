# Market Data Pipeline Map

Generated by Ask mode exploration of the Perl source files.

## Pipeline Overview

Three-stage batch pipeline processing end-of-day market data records.

## Stage 1: Ingest (ingest.pl / ingest.py)

**Purpose:** Read raw market data records from CSV and enrich with OpenFIGI identifiers.

**Inputs:** data/sample_input.csv (columns: record_id, instrument_id, id_type, exchange_code, price, volume, timestamp)

**External dependency:** OpenFIGI API (api.openfigi.com/v2/mapping) via FigiClient / figi_client.py

**Rate limiting:** 100 requests per 60-second window. Retries up to 5 times on HTTP 429.

**Key logic:** Counts records by exchange_code, ranks exchanges by frequency, appends lookup_count and exchange_rank columns.

**Outputs:** Enriched CSV with additional columns: figi, lookup_count, exchange_rank

## Stage 2: Transform (transform.pl / transform.py)

**Purpose:** Normalise prices, calculate notional values, classify trade sizes, validate timestamps.

**Inputs:** Output of Stage 1

**Key logic:**
- Price normalised to 4 decimal places
- Notional = price * volume
- Size bucket: BLOCK >= 1,000,000 / LARGE >= 100,000 / MID >= 10,000 / SMALL < 10,000
- figi_resolved = 1 if FIGI was resolved, 0 if UNKNOWN
- ts_valid = 1 if timestamp matches YYYY-MM-DD HH:MM:SS

**Outputs:** Transformed CSV with additional columns: notional, size_bucket, figi_resolved, ts_valid

## Stage 3: Validate (validate.pl / validate.py)

**Purpose:** Validate all transformed records against the registered schema. Exit non-zero on critical violations.

**Critical checks:** record_id uniqueness, instrument_id presence, price format (4dp positive), volume (positive integer), figi_resolved = 1

**Warning checks:** ts_valid = 1, notional > 0

**Outputs:** Validation report to stdout. Exit code 0 (PASS) or 1 (FAIL).

## Known Issue: Sort Stability Regression

The Perl ingest uses `reverse sort` to rank exchanges, which reverses tied elements.
Python's `sorted(..., reverse=True)` preserves insertion order for ties.
With all 5 exchanges tied at 4 records each, all 20 output records differ in exchange_rank.
This regression is visible in the parity check but invisible to pytest.
